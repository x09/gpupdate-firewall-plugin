# Плагин x09_firewall для gpupdate

Плагин расширяет систему групповых политик gpupdate (GPOA) на ОС Альт
возможностью управлять межсетевым экраном (iptables) централизованно, через
групповые политики домена.

Правила задаются ADMX-шаблоном «Управление правилами брандмауэра» и
применяются на клиентских машинах при каждом запуске `gpupdate`.

## Как это работает

1. Администратор в редакторе групповых политик заполняет список правил
   (ADMX-политика `FirewallRulesList`). Каждое правило — одна строка списка.
2. Правила сохраняются в SYSVOL и попадают в реестр клиента по пути
   `Software/Policies/x09/Firewall` как значения `Rule1`, `Rule2` …
3. При запуске `gpupdate` менеджер плагинов вызывает этот плагин в машинном
   контексте (с правами root).
4. Плагин читает правила, транслирует их в правила iptables и применяет их
   в выделенные пользовательские цепочки.

## Формат правила

Каждое правило — одна строка вида «ключ=значение», поля разделяются `;`:

```
Action=Allow;Direction=In;Protocol=TCP;Port=80;Source=10.0.0.0/24;Destination=192.168.1.1
```

Регистр и порядок полей значения не имеют.

| Поле          | Обязательное | Значения                                                    |
|---------------|--------------|-------------------------------------------------------------|
| `Action`      | да           | `Allow`, `Deny`, `Reject`                                   |
| `Direction`   | да           | `In` (входящий), `Out` (исходящий)                          |
| `Protocol`    | да           | `TCP`, `UDP`                                                |
| `Port`        | нет          | одиночный порт (`80`), диапазон (`53-153`) или список (`22,80,443`) |
| `Source`      | нет          | IP-адрес или сеть CIDR                                      |
| `Destination` | нет          | IP-адрес или сеть CIDR                                      |

**Примечания:**
- Трансляция действия: `Allow → ACCEPT`, `Deny → DROP`, `Reject → REJECT`.
- Поле `Port` может содержать:
  - одиночный порт: `Port=80` → `--dport 80`
  - диапазон портов: `Port=53-153` → `-m multiport --dports 53-153`
  - список портов: `Port=22,80,443` → `-m multiport --dports 22,80,443`
- При использовании диапазонов и списков автоматически применяется модуль `multiport` iptables.

Некорректное правило пропускается с записью предупреждения в журнал;
обработка остальных правил продолжается.

## Модель применения к iptables

Плагин не изменяет напрямую системные цепочки `INPUT`/`OUTPUT`, а работает
через собственные цепочки:

- `FW_PLUGIN_INPUT` — для правил с `Direction=In`;
- `FW_PLUGIN_OUTPUT` — для правил с `Direction=Out`.

При каждом запуске:

1. Пользовательские цепочки создаются при отсутствии, и в системные цепочки
   `INPUT`/`OUTPUT` первым правилом добавляется переход `-j` в них (идемпотентно).
2. Содержимое **только** пользовательских цепочек очищается (`-F`) и
   наполняется заново из политики.

Такой подход:

- не затрагивает прочие правила брандмауэра на машине;
- не блокирует трафик по умолчанию — в конце наших цепочек происходит неявный
  возврат (`RETURN`) в системную цепочку, поэтому доступ (например, по SSH) не
  разрывается, даже если политика пуста.

## Персистентность

После применения плагин сохраняет текущий набор правил командой
`iptables-save` в файл `/etc/sysconfig/iptables` (штатный механизм ALT), чтобы
правила сохранялись после перезагрузки. Путь задаётся константой
`IPTABLES_SAVE_PATH` в коде плагина.

## Ограничения текущей версии

- Поддерживается только классический `iptables` (IPv4), цепочки `INPUT`/`OUTPUT`.
- IPv6 (`ip6tables`) и бэкенд `nftables` не поддерживаются.
- Порт применяется как порт назначения (`--dport`) для обоих направлений.
- Для диапазонов и списков портов требуется модуль `multiport` ядра (загружен по умолчанию в большинстве систем).

## Установка

### Ручной способ

#### Установка admx шаблонов

На контроллере домена, admx/adml файлы положить в /usr/share/PolicyDefinitions

```
/usr/share/PolicyDefinitions/x09-Firewall.admx
/usr/share/PolicyDefinitions/{ru-RU,en-US}/x09-Firewall.adml
```

и загрузить в SysVol командой 

```
samba-tool gpo admxload -UAdministrator
```

#### Установка плагина на клиенте

Плагин ставится **плоским файлом** в `/usr/lib/gpoa/plugins/` (без
подкаталога), переводы — в общий каталог `locale/` рядом с плагином.
Каталог `/usr/lib/gpoa/` предоставляется пакетом `gpoa-lib` — вручную его
обычно создавать не нужно.

```
/usr/lib/gpoa/plugins/x09_firewall.py
/usr/lib/gpoa/plugins/locale/ru_RU/LC_MESSAGES/x09_firewall.mo
/usr/lib/gpoa/plugins/locale/en_US/LC_MESSAGES/x09_firewall.mo
```

### Автоматический способ

Установить rpm пакеты

- `admx-x09-firewall` - пакет с admx шаблонами (на КД)
- `gpupdate-firewall-plugin` - пакет с плагином (на клиента)

## Локализация

Сообщения журнала переведены на русский и английский языки (GNU gettext,
домен `x09_firewall`). Отображаемый язык определяется локалью системы.

Пересборка переводов после изменения `.po`:

```bash
msgfmt locale/ru_RU/LC_MESSAGES/x09_firewall.po -o locale/ru_RU/LC_MESSAGES/x09_firewall.mo
msgfmt locale/en_US/LC_MESSAGES/x09_firewall.po -o locale/en_US/LC_MESSAGES/x09_firewall.mo
```
